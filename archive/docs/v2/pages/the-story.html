The Complete Story

From Component Definition to Generated UI Specification

Why modern user interface generation demands an organized execution engine.

The Challenge of Building UI

Building a user interface requires more than data. Each component needs a structure, a set of instructions, and configuration options that define how it should be built.

"For example, creating a table requires a base table structure, instructions to generate its columns and rows, and optional features such as serial numbers or search."

The challenge is to execute these requirements in an organized and reusable way across different screens, components, and applications without re-writing custom loops each time.

The Solution

An Instruction Execution Engine

json-renderers-run-instructions provides a common execution engine that takes a component definition and transforms it into a completed JSON specification.

It standardizes how specifications are built into a clean 6-stage pipeline:

  1. 1. Select the Component: The application specifies the component using a main key and sub key (e.g. table.simple).
  2. 2. Retrieve the Definition: The engine retrieves the corresponding definition from spec-repo. The definition identifies the base specification, required instructions, and available options.
  3. 3. Prepare the Base Specification: The engine creates an independent copy of the selected base structure. This becomes the starting point for building the component.
  4. 4. Execute the Instructions: The engine passes the instructions, base structure, and input data to json-renderers-run-instructions-steps. These instructions update the base specification according to the selected component definition.
  5. 5. Apply Configuration Options: The engine passes the selected options to runOptions. Supported features are applied to the generated specification.
  6. 6. Return the Completed Specification: The engine returns the completed JSON specification. This output can then be passed to jsonToDom to create and display the actual HTML elements in the browser.

One Engine, Multiple Components

The same execution flow can be used for different component definitions, such as:

Tables
Accordions
Cards
Lists
Select components
Other supported UI structures

The component definition and its instructions determine what gets built — the engine remains uniform and predictable.

The Main Responsibility

json-renderers-run-instructions does not define every HTML component itself, nor does its main function directly create browser DOM elements.

Its responsibility is to coordinate component definitions, execute their instructions, apply configuration options, and return the resulting JSON specification.

In Simple Terms:
  • The definition tells the engine what to build.
  • The instructions tell it how to build it.
  • The options customize the result.
  • The engine executes these steps and returns the completed JSON specification.
